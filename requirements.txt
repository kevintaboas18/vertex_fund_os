# M-13: rangos con techo. Sin techo, un `pip install` futuro puede traer una
# major con cambios incompatibles y romper el scoring en silencio.
# Los techos son de MAJOR: 2006 tests pasan con pandas 3.0.3 y numpy 2.5.1,
# asi que fijar <3 habria forzado un downgrade sin motivo.
#
# ─────────────────────────────────────────────────────────────────────────────
#  POR QUE IMPORTAN LOS TECHOS: un despliegue no toca el codigo y falla igual
#
#  Render corre `pip install -r requirements.txt` EN CADA DESPLIEGUE, sin
#  lockfile. Una dependencia sin techo resuelve a lo mas nuevo que exista ESE
#  DIA, asi que el mismo commit puede instalar cosas distintas el martes y el
#  jueves. Cuando eso rompe algo, el sintoma es exactamente «antes funcionaba y
#  ahora sale failed» sin que nadie haya tocado una linea — y el commit
#  culpable no existe, porque el cambio ocurrio fuera del repositorio.
#
#  Tres dependencias estaban sin techo pese a que este mismo archivo dice en su
#  primera linea que todas lo llevan: `anthropic`, `matplotlib` y
#  `cryptography`. Las tres tienen ahora el techo de su siguiente major.
#
#  Verificado el 2026-08-08 en un venv limpio, con la resolucion que Render
#  obtiene hoy: fastapi 0.141.1 · starlette 1.6.0 · pandas 3.0.5 · numpy 2.4.6
#  · scipy 1.17.1 · matplotlib 3.11.1 · anthropic 0.121.0 · cryptography 50.0.0
#  · yfinance 1.5.2. Build OK, arranque OK, health check 200 en 4 s, y los
#  3.487 tests en verde.
#
#  Para reproducir el despliegue entero sin esperar a Render:
#      python engine/scripts/preflight_render.py --remoto --instalar
# ─────────────────────────────────────────────────────────────────────────────
